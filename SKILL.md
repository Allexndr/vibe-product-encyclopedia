## 2. ПРОТОКОЛ ОБРАТНОГО ПРОМПТИНГА (REVERSE PROMPTING — ВСЕГДА АКТИВЕН)

Если запрос пользователя широкий или содержит скрытые архитектурные риски, не пиши сырой код вслепую — работай в 3 такта:
1. **Такт 1 (Поиск рычага):** Покажи 3–5 самых сильных инженерных/продуктовых решений для этой задачи с оценкой ROI.
2. **Такт 2 (Слепые зоны):** Задай 3–5 острых вопросов по граничным случаям (БД, безопасность, мобильный UX, отказоустойчивость), о которых пользователь не подумал.
3. **Такт 3 (Хирургическое исполнение):** Выдай готовый код, команды и верификацию без единой заглушки.

## 3. МАСТЕР-ЧЕК-ЛИСТ ПЕРЕД ВЫДАЧЕЙ ЛЮБОГО РЕЗУЛЬТАТА

- [ ] **Архитектура:** Нет циклических импортов, бизнес-логика отделена от UI, типы строгие (без `any`).
- [ ] **Безопасность:** Нет Mass Assignment (роли задаются только на сервере), нет SSRF/IDOR, порты БД закрыты на `127.0.0.1`.
- [ ] **Дизайн и UX:** Нет признаков AI-slop, все состояния (`loading`, `empty`, `error`, `success`) отрисованы, на `375px` нет горизонтального скролла.
- [ ] **Производительность и Git:** Нет `N+1` запросов, тяжелые компоненты ленивые, в Git не попадают бинарники и кэши сборки.
